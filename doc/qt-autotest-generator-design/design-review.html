知识图谱 MCP 硬门禁

Iron Law #1 — 无图谱索引不执行，不降级到文件扫描 / LSP

为什么不降级？

  • 文件扫描无法获取 调用链（trace_path）
  • 无法做 继承检测（DBus/并发基类）
  • 无法计算 in_degree P75 百分位
  • 无法 Cypher 查询 传递依赖
  • 降级评分失真 → 分级无效 → 门禁形同虚设

双提供方策略

  • 远端优先：remote-codebase-memory-mcp
  • 本地兜底：codebase-memory-mcp（≥0.8.0）
  • 互斥使用：不混用多个提供方
  • environment_check 一次性解析
  • 12000 方法端到端仅 ~2 秒

核心 MCP 工具

search_graph
全量类/方法分页
trace_path
出向调用链追踪
get_code_snippet
方法级源码
query_graph
Cypher 继承/IMPORTS

实测踩坑

  • is_exported 不可靠 — 已移除
  • in_degree 对 Qt 回调失效
  • P75 必须排除零值
  • MCP 不支持 percentileCont()

核心 设计创新 总结

让单测生成从「手工拼凑」变成「知识图谱驱动的工程化闭环」

知识图谱硬门禁

拒绝降级到文件扫描。图谱提供调用链、继承链、传递依赖——这些是评分和 stub 决策的基础设施，没有它们整个体系会崩塌。

多因子评分 → 分级门禁

不是一刀切。15+ 因子加权评分区分 high/mid/low，对应不同覆盖率阈值。核心契约方法 90% 行覆盖，辅助方法 60% 即可。

对账 + 差异路由

每次运行先比对 git SHA。新增→补全、变更→重生、删除→主动清理、分支切换→stale 标记。源码演进了，测试跟着演进。

闭环验证链

逐类闭环：trace→gen→build→check。编译不过不报完成，覆盖率不过自检拦截，变异测试补有效性。5 层质量保障层层递进。

安全边界

不修源码、只 APPEND 不改已有、变异测试四铁律、过时测试主动清理不等编译报错。每条铁律背后都是一次真实踩坑的教训。

可选增强不干扰

Mode 4/5 可选增强：不占迭代预算、不污染覆盖率、不更新 inventory、不自动改测试。核心流程干净，增强按需接入。
