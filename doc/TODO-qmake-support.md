## 二、CMake ↔ qmake 关键映射

| CMake | qmake | 难度 |
|-------|-------|------|
| `CMakeLists.txt` | `.pro` 文件 | 直接映射 |
| `add_subdirectory()` | `SUBDIRS +=` | 直接映射 |
| `target_link_libraries()` | `LIBS +=` | 直接映射 |
| `target_include_directories()` | `INCLUDEPATH +=` | 直接映射 |
| `find_package(Qt5 ...)` | `QT += core widgets` | 语法不同但一一对应 |
| `file(GLOB TEST_SOURCES)` | `SOURCES += test_*.cpp` | qmake 支持 glob |
| `cmake -DBUILD_TESTS=ON` | qmake 无条件编译 subdirs | 需用 `CONFIG+=build_tests` 或 `.pro` 条件 |
| `cmake --build .` | `make -j$(nproc)` | 更简单 |
| `gtest_discover_tests()` | 手动 `make check` 或直接运行 | 小差异 |

### 3.1 qmake-autotests.pro 草稿

```pro
# autotests.pro — Unit test sub-project
# Generated by qt-autotest-generator

TEMPLATE = subdirs
CONFIG += ordered

# Test subdirectories (appended by test_writer)
# {ADD_SUBDIRECTORIES}
```

### 3.2 qmake-submodule.pro 草稿

```pro
# test_{module_name}.pro
# Generated by qt-autotest-generator

QT += testlib core
QT += {QT_MODULES}  # core / core widgets 等

TEMPLATE = app
CONFIG += c++17 console testcase
CONFIG -= app_bundle

SOURCES += test_*.cpp
HEADERS +=

# stub-ext
SOURCES += $$PWD/../3rdparty/stub/stub-shadow.cpp
INCLUDEPATH += $$PWD/../3rdparty/stub

# 项目源码
INCLUDEPATH += $$PWD/../../{source_module_path}
SOURCES += $$files($$PWD/../../{source_module_path}/*.cpp, true)

# 链接项目库（如有）
LIBS += {PROJECT_LIBRARIES}

# 覆盖率（Debug 模式）
CONFIG(debug, debug|release) {
    QMAKE_CXXFLAGS += -fprofile-arcs -ftest-coverage -O0
    QMAKE_LFLAGS += -lgcov
    LIBS += -lgcov
}

# GTest（系统安装或 pkg-config）
LIBS += -lgtest -lgtest_main -lpthread
```

## 四、主要风险点

1. **qmake 的 `SUBDIRS` 追加**：不像 CMake 可以在 `add_subdirectory(src)` 后面插一行，qmake 的 `.pro` 文件中 `SUBDIRS` 需要同时在两个地方声明（列表 + 子目录 `.pro` 路径），格式略复杂：

   ```pro
   SUBDIRS += autotests
   autotests.subdir = autotests
   autotests.depends = src
   ```

2. **qmake 无 `option(BUILD_TESTS)` 等价物**：需要用 `contains(CONFIG, build_tests)` 条件编译，或者直接无条件编译 autotests 子目录：

   ```pro
   # 根 .pro
   contains(CONFIG, build_tests) {
       SUBDIRS += autotests
   }
   ```
   编译时加 `qmake CONFIG+=build_tests` 或 `make CONFIG+=build_tests`。

3. **混合构建项目**：部分 DDE 项目是顶层 CMake + 子目录 qmake，需要支持探测并走 CMake 路径（CMake 可调 qmake 子项目，反之不行）。**建议**：检测到根目录有 `CMakeLists.txt` 走 CMake 路径，只有 `.pro` 没有 `CMakeLists.txt` 才走 qmake 路径。

4. **qmake glob 限制**：`$$files()` 函数在较老 qmake 版本中不可用，可能需要显式列出 SOURCES。备选：用 `SOURCES += $$files($$PWD/*.cpp)` 依赖 Qt 5.12+，旧版需手动枚举。

5. **GTest 集成**：CMake 有 `find_package(GTest)` + `GTest::gtest`，qmake 需手动 `LIBS += -lgtest -lgtest_main` 或用 `pkg-config`：`CONFIG += link_pkgconfig` + `PKGCONFIG += gtest`。

## 五、实施计划（分步）

### Step 1: 项目探测扩展（~1h）

**文件**：`references/environment-check.md`

在 §0 增加：

```bash
# 探测构建系统
if [ -f "${project_path}/CMakeLists.txt" ]; then
    build_system="cmake"
elif [ -f "${project_path}/*.pro" ]; then
    build_system="qmake"
else
    # 硬终止：非 CMake/qMake 项目
    exit 1
fi
```

写入内存变量 `build_system`，后续所有步骤按此分支。

### Step 2: 新增 qmake 模板（~2-3h）

**新增文件**：
- `templates/qmake-autotests.pro`
- `templates/qmake-submodule.pro`

**逻辑**：与现有 CMake 模板一一对应，占位符命名保持一致（`{module_name}` / `{QT_VERSION}` / `{PROJECT_LIBRARIES}` / `{source_module_path}` 等），方便 `test-code-gen.md` 统一替换。

### Step 3: framework-builder 分支（~1-2h）

**文件**：`references/framework-builder.md`

按 `build_system` 分支：
- CMake：走现有逻辑（不动）
- qmake：
  - 复制 stub-ext（同）
  - 生成 `autotests/autotests.pro`（替代 CMakeLists.txt）
  - 生成 `autotests/<module>/test_<class>.pro`（替代子 CMakeLists.txt）
  - 修改根 `.pro`：追加 `SUBDIRS += autotests` + `autotests.subdir = autotests` + `contains(CONFIG, build_tests)` 条件
  - 验证框架编译：`qmake && make` 替代 `cmake && cmake --build`

### Step 4: 编译验证适配（~1h）

**文件**：`references/build-verifier.md` + `scripts/generate-runner.sh`

编译命令按 `build_system` 分支：
- CMake：`cmake .. -DBUILD_TESTS=ON && cmake --build .`
- qmake：`qmake .. CONFIG+=build_tests && make -j$(nproc)`

运行测试命令不变。

### Step 5: 小修（~0.5h）

- `references/test-code-gen.md` §5：生成 `.pro` 文件（按 build_system 分支）
- `references/code-committer.md`：提交列表加 `*.pro`
- `SKILL.md`：description 去掉"非 CMake"；不触发条件改为"非 Qt 或非 CMake/qMake 项目"
- `scripts/collect-coverage-report.py`：Step 1 编译命令加 qmake 分支
- `references/dependency-tracer.md`：基本不用动（`source_dirs` 概念通用）

### Step 6: 测试验证（~1-2h）

找一个纯 qmake 的 Qt 项目（或从 examples/ 中建一个 sample-qmake-project），完整跑 Mode 1 → Mode 2 → Mode 3 流程。
