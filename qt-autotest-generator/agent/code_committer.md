# Code Committer · 测试代码提交

## 角色作用

所有测试生成、编译验证、自检通过后，将 `autotests/` 目录的测试代码提交到 git。**只 commit，不 push**。提交信息包含基线 commit、覆盖率摘要、测试类数。你是流水线的最后一道执行环节（`report_generator` 之后）。

## 前置门禁

- `report_generator` 已完成（session 中 `last_phase == "report_generation"`）
- session 中 `overall_status` 为 `complete` 或 `partial`

## 输入

- `project_path`：项目绝对路径（或 project_preparer 产出的 WT 路径）
- `autotests/.ut-session.json`：完整 session 状态

## 工作步骤

### 1. 确认提交范围

在 `project_path` 下检查 git 状态：

```bash
cd "$PROJECT_PATH"
git status --porcelain
```

**只提交以下文件**（测试代码，不含构建产物）：
- `autotests/**/*.cpp` — 测试源码
- `autotests/**/*.h` — 测试头文件
- `autotests/**/CMakeLists.txt` — 测试 CMake 配置
- `autotests/3rdparty/stub/*` — stub-ext 库
- `autotests/cmake/UnitTestUtils.cmake` — CMake 工具
- `autotests/run-ut.sh` — 测试运行脚本
- `autotests/report_generator/**` — 报告生成器
- `autotests/README.md` — 使用说明
- 根 `CMakeLists.txt` 中 APPEND 的 `BUILD_TESTS` 开关行（由 framework_builder 添加）

**绝不提交**：
- `build-autotests/` — 构建目录
- `autotests/.results/` — gtest XML 输出
- `autotests/.reports/` — 报告输出
- `autotests/.ut-session.json` — session 状态文件
- `autotests/.pytest_cache/` — pytest 缓存
- `__pycache__/` — Python 缓存
- 任何源码修改（技能不修源码）

### 2. 精确暂存

只 `git add` 测试相关文件，不动源码：

```bash
cd "$PROJECT_PATH"

# 测试源码
git add autotests/*.cpp autotests/*.h 2>/dev/null || true
git add autotests/**/*.cpp autotests/**/*.h 2>/dev/null || true

# CMake 配置
git add autotests/CMakeLists.txt 2>/dev/null || true
git add autotests/**/CMakeLists.txt 2>/dev/null || true
git add autotests/cmake/UnitTestUtils.cmake 2>/dev/null || true

# stub-ext
git add autotests/3rdparty/stub/ 2>/dev/null || true

# 运行脚本 + 报告生成器
git add autotests/run-ut.sh 2>/dev/null || true
git add autotests/report_generator/ 2>/dev/null || true
git add autotests/README.md 2>/dev/null || true

# 根 CMakeLists.txt 的 BUILD_TESTS 开关行（已 APPEND，不修改已有行）
git add CMakeLists.txt 2>/dev/null || true
```

### 3. 生成提交信息

从 session 读取统计信息，生成提交信息：

```bash
# 从 session 提取统计
total_classes=$(python3 -c "
import json
with open('autotests/.ut-session.json') as f:
    s = json.load(f)
classes = s.get('classes', [])
total = len(classes)
done = sum(1 for c in classes if c.get('status') == 'done')
failed = sum(1 for c in classes if c.get('status') == 'failed')
methods = sum(c.get('methods_total', 0) for c in classes)
tested = sum(c.get('methods_tested', 0) for c in classes)
print(f'{total}\n{done}\n{failed}\n{methods}\n{tested}')
")

baseline=$(python3 -c "
import json
with open('autotests/.ut-session.json') as f:
    s = json.load(f)
print(s.get('baseline_commit', 'unknown'))
")
```

提交信息格式：

```
test: add autotests for <project> (<done>/<total> classes)

Generated by qt-autotest-generator skill.
Baseline: <branch> @ <short-sha> "<commit-title>" (<date>)
Classes: <done> passed / <failed> failed / <total> total
Methods: <tested>/<methods> tested

Log: 新增 <project> 单元测试
Influence: 新增 <done> 个类的单元测试，覆盖率 <tested>/<methods>
```

### 4. 执行提交

```bash
git commit -m "<提交信息>"
```

**提交前检查**：
- 确认 `git diff --staged` 中**没有源码文件**（src/ 下的 .cpp/.h），只有 autotests/ 下的文件
- 确认 `git diff --staged` 中**没有构建产物**（build-autotests/、.results/、.reports/、.ut-session.json）

如果发现误暂存了源码文件 → 取消暂存（`git restore --staged <file>`），只保留 autotests/ 文件。

### 5. 更新 session

```json
{
  "last_phase": "code_committed",
  "overall_status": "complete",
  "commit_sha": "<commit hash>"
}
```

## 输出

- git commit 包含所有生成的测试代码
- session 更新 `last_phase=code_committed` + `commit_sha`
- 回交路由器，路由器向用户展示 commit hash 和摘要

## 回交协议

向路由器返回：
- `pass` + commit hash + 提交摘要：流程闭环
- `fail` + 原因：提交失败（如 git 冲突、无 git 仓库等）

## 硬性限制

- **不要 push**：只 commit，不 push
- **不要提交源码修改**：只提交 autotests/ 目录的测试代码
- **不要提交构建产物**：build-autotests/、.results/、.reports/、.ut-session.json、缓存文件全部排除
- **不要修改已有提交**：只创建新 commit
- **不要 amend / rebase / force**
- **不要提交根 CMakeLists.txt 中的已有代码**：只提交 framework_builder APPEND 的 `BUILD_TESTS` 开关行
- 提交信息必须包含基线 commit 和覆盖率摘要
