# 工作原则

## skill 驱动

单测生成、依赖追踪、编译验证、覆盖率自检、批次提交等全流程走 qt-autotest-generator skill 的阶段化派发（reconcile 对账 → environment_check → framework_builder → 逐类循环 class_analyzer→dependency_tracer→test_writer→build_verifier→self_checker → 批次提交 code_committer+self_checker(commit_check) → report_generator），由路由队长按 `autotests/.ut-session.json` 状态派发专职 subagent，不凭经验跳步、不手写测试。skill 内的 Iron Laws 必须遵守——知识图谱 MCP 硬门禁（无图谱不执行、不降级 LSP，远端优先本地兜底互斥使用其一）、`autotests/` 固定目录名、Google Test only、不修源码（疑似缺陷只标红交还用户）、强制编译+运行验证门禁（不通过不报完成）、函数覆盖率门禁（默认 80%，可由用户指定）、只 APPEND 不改已有、状态写 session 文件不靠内存、逐类闭环单类失败不阻塞、只 commit 不 push。

## 门禁驱动而非人为确认

推进门禁是三项硬指标——

1. 知识图谱 MCP ready
2. 每类 build_verifier 编译+运行双通过
3. self_checker 覆盖率/命名/SPDX/stub 自检通过

三项全过才标记 done。任一不过按双信号路由修复：

- 编译/运行失败 → `failure_repairer`
- 方法名差集非空或 lcov 函数覆盖率 < 阈值 → `incremental_updater`

`failure_repairer` 重试耗尽 → 标 failed + failure_reason + 跳过，不阻塞其他类。疑似源码缺陷（compile/runtime/logic 矛盾）只标红、记 failure_reason、在 `report_generator` 报告里标红输出，**不自行修源码**；`report_generator` 返回 `source_defect_count > 0` 时向用户输出醒目提示，请用户确认后再处理。

## 批次提交 + 提交规范自检

每批次（一轮批量生成/增量补全/失败修复/源码变更对账）所有目标类 self_checker 处理完毕（含 done/failed/skipped）后，立即派发 `code_committer` 增量提交本批次新完成类（跳过 `committed_classes` 已记录的类，防重提），再派发 `self_checker(commit_check=true)` 自检四项——

- 已提交完整性
- 未误提交源码
- 未误提交构建产物
- 提交信息格式规范

自检不过派发 `code_committer` 修正（message 不规范 amend 本批次未 push commit；文件误提交必须新 commit 撤销）后再自检。**所有 code_committer 仅 commit，不 push**。`report_generator` 收尾时测试代码已全部入库，不再触发 `code_committer`。

## 提交信息规范

每批次提交信息须含：

- 本批次完成类清单
- 批次统计（总数/通过/失败/跳过）
- 基线 commit（`baseline_commit` + `baseline_title` + `baseline_date`）

subject 遵循项目历史 commit 风格，不写"AI 分析"/"Generated by AI"字样。可提交：测试代码、CMake 追加、stub-ext 内置文件。**一律不入 commit**：session 文件 `.ut-session.json`、构建产物（`build/`、`CMakeCache.txt`、`*.o` 等）、用户源码修改。

## 产物归宿

- 测试代码 → git commit（批次增量提交）
- HTML/CSV 报告 → `autotests/` 下由 `report_generator` 固定收尾生成
- session 状态 → `autotests/.ut-session.json`（应加入 `.gitignore`）

若在 multica/GitHub issue 上跟踪单测生成任务，可将 `report_generator` 产出的 HTML/CSV 报告与每批次提交摘要作为 issue 附件上传，供用户在平台查阅；每次批次提交或报告更新后即上传。
